# Braces depth security correction

GHSA-vfj7-8cjw-p6xm / CVE-2026-93687 affects braces <=3.0.3. npm still publishes3.0.3 aslatest on2026-10-22; the advisory lists no fixed release. Marketing uses it through chokidar and micromatch in Tailwind/file-watching and Next ESLint tooling. This establishes tooling exposure, not an exploitable deployed route. The marketing site is statically exported.

The exact patch is reused from the independently tested Avercare backport of https://github.com/micromatch/braces/pull/72 at d0d575e55e74a4e0218e5248fafb79efc3e54ebb. It limits brace/parenthesis parser and direct AST walker depth to100 and permits stricter caller limits. It preserves the released stringify parent behavior to avoid unrelated escaping changes. Upstream PR72 was closed without merging on2026-10-05; this is a locally maintained correction, not a maintainer-approved upstream release. Later fork improvements are separate from the reviewed depth-only patch; fractional caller limits and cyclic caller-constructed AST behavior are not claimed fixed here. Neither can raise the hard100-level depth ceiling.

`npm ci` applies the pinned patch in postinstall. `braces-manifest.json` pins original and patched source hashes, exact patch SHA256, locked package version and immediate consumers. Missing/changed patches, package versions, source bytes, additional consumers and an unavailable patch executable fail installation or verification. The patch command uses zero fuzz. The guard checks every locked/installed braces copy and the version actually resolved by each consumer.

`npm run security:test` checks 4,998-level input (the published source reproduces a call-stack overflow),100/101 boundaries, attempted bound overrides, public AST overloads, ordinary expansion/ranges/escaping and real micromatch brace expansion. Tests also prove source/patch/version/consumer tampering and unknown/mixed/cyclic audit causes fail closed. The patch uses the system `patch` command, available on macOS and the Ubuntu CI runner; unsupported environments fail rather than silently installing an unpatched copy.

`npm run security:audit` saves raw npm audit JSON and stderr/status separately, verifies installed source and behavior, then writes a separate disposition. The registry report continues to show affected3.0.3. Only advisory ID1240992 with its exact package/dependency/URL/range/severity and transitive records entirely caused by it receive verified-local-correction credit. New advisories, missing/invalid audit data, package-path discrepancies, source drift and failed probes remain errors. This is not a clean raw audit and no advisory is ignored. CI uploads the raw report and correction evidence even on failure.

Related issue: https://github.com/justinGrosvenor/alignmenter/issues/31 . Keep upstream replacement tracked. Once a reviewed fixed upstream release exists, upgrade, run these regressions, then remove the postinstall patch, manifest and one advisory disposition together.
